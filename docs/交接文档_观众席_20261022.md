## 三、接手前必须知道的 6 件事

### 1. 测试用 `arc()` 统计人数——这是硬约定

6 项观众测试里，5 项以 **`arc()` 调用次数**统计"屏幕上有多少观众"，
`crowd-team-consistency` 还依赖 **`arc` 时的 `fillStyle` = 该观众队色**。

> **任何新画法都必须保持：每位观众恰好 1 次 `arc`，且 `arc` 前 `fillStyle` 已设为队色。**

当前的实现把这 1 次 `arc` 用在"棒尖亮点"上——它**不只是装饰**，是计数契约的承载体。

### 2. 测试桩只实现 ctx 的最小子集

实测桩里**没有**这些方法，用到就抛 `TypeError`：

```
fillRect  closePath  save  restore  rotate
```

**对策**：改 ctx 状态时用「记原值 → 改 → 还原」，不要用 `save/restore`；
闭合路径用"回到起点"而不是 `closePath`。

### 3. `drawPerson`（旧火柴人）必须保留

`seated-crowd-test` 用**投影点序列的固定索引**（如 `rec[13]`）断言"手在肩之上/之下"。
它验证的是 `seatedPose()` 的骨架逻辑（含历史 bug `adbbd20`）。

> **不要改写 `drawPerson`**，新画法一律走新函数 + `CROWD_STYLE` 开关。

### 4. 人口数没有硬编码，可以安全调密度

所有测试都走 `crowdLayout()` 动态取数，**没有任何地方写死 376**。
上一轮把步长 `0.46 → 0.30`（376 → 576），测试零改动全绿。

### 5. 动画层与静态层必须用同一个画法

得分时观众会烘焙进"动画层"（30Hz）。`49c822a` 修的 bug 就是这里：
**动画层曾硬编码 `drawPerson`**，导致"平静是应援棒、一得分变火柴人"。

> 以后再加画法分支，**两处都要改**：`drawCrowd`（静态/直画）与 `rebuildAnimCache`（动画层）。

### 6. 贴图加载有坑

`drawImage` 收到 **broken 状态**的 Image 会抛 `InvalidStateError`。
必须先判 `img.complete && img.naturalWidth > 0`。

另外：素材是「下亮上淡」，绘制时要**反向**（`drawImage` 用负高度）才能让亮端落在握点。

## 五、欢呼机制怎么接的（别重复造轮子）

全项目**已有**这套机制，观众席只是消费者：

```
state.js:681   app.fan.cheer[winner] = 1;  app.fan.shake[1-winner] = 1;
loop.js:101    cheer/shake 每秒衰减 0.6
render.js      drawCrowd 把 fan.cheer[team] 作为标量 c 传给画法
```

第一轮：`c` 驱动**挥速**与**亮度**。第二轮：`c` 驱动**状态机**（摆幅/爆闪/光浪/对方压暗），
衰减仍由 `loop.js` 的 `0.6/s` 负责，**依然没有新增状态**。

> 阵营左右：`render.js` 的 `team` 映射——世界 `x<0` 为己方（左），`x>0` 为敌方（右）。
> 队色来自 `setCrowdColors([teams[0].color, teams[1].color])`（`modes.js`），跟着旗帜走。
> 第二轮的过渡带混色基于 `FAN_RGB`（由 `FAN_COL` 字符串解析而来），`setCrowdColors()` 之后仍然生效。
