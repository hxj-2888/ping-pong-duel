## 一、机位怎么定的（不是手调，是解出来的）

`tools/solve-camera.cjs` 用参考图上量出的地标做网格搜索。

### ⚠ v7 的全套错误根因：屏幕左右约定反了

`Camera.set` 里 `right = cross(fwd, up)`；相机在 -z 朝 +z 看时 `right ≈ (-1,0,0)`，
即**世界 +x 投到屏幕左侧**。旧版 cost 写 `lft.x/W → 0.358`（以为世界 -x 在屏幕左），
两个 x 项全程反向 ⇒ 台宽约束被优化到错误方向 ⇒ 撞边界 ⇒ **误判"参考图透视无解、只能折中"**。

修正约定后 cost 从 0.14+ 降到 **0.0057**，六个地标同时命中：

| 地标 | 参考图读数 | v7（折中） | v8（13.9°） | **v8b（30.0°）** |
|---|---|---|---|---|
| 球台远边 y/H | 0.545 | 0.562 | 0.538 | **0.509** |
| 球台近边 y/H | 0.70 | 0.739 | 0.717 | **0.846** |
| 球台宽（中线） | 0.284W | 0.188W | 0.253W | **0.252W** |
| 自己球员头顶 y/H | 0.58 | 0.661 | 0.528 | **0.715** |
| 自己球员脚 y/H | 0.91 | 1.008（出画） | 0.925 | **1.036（出画）** |
| 对方球员头顶 y/H | 0.40 | 0.420 | 0.365 | **0.332** |
| **俯角** | — | — | 13.9° | **30.0°（用户指定）** |

```js
// public/js/app/render.js · makeCam()   〔v8b：用户指定俯角 30°〕
const eye = PPD.TTG.v3(camX, 7.43, (side === 0 ? -10.10 : 10.10) + camX * 0.05);
const look = PPD.TTG.v3(camX * 0.55, 1.60, 0);
const focal = vw * 2.00;
// 俯角 = atan((eyeY - lookY) / |eyeZ|) = atan(5.83 / 10.10) = 30.0°
// （v8 原值 3.80 / 1.30 / 1.75×vw ⇒ 13.9°）
```

> 机位从"贴近球台的中景"变成"退远 + 长焦"的转播机位。副作用是好的：
> 分屏竖屏时纵向视野反而比旧机位窄（旧 0.86× 在 195×844 视口里纵向 FOV 151%，新 2.00× 只有 92°）。
>
>
> ⚠ **俯角一变，三个"按投影点定位"的下游都要跟着查**（v8b 实测踩坑）：
> ① `drawFloorBg` 近端地板块的起点原来用 `project(0,0,-TBL)`（台前**地面**点），
> 俯角 30° 时它被压到 0.991H，整块三色调地板只剩底部 6% ⇒ 改取**台面远边**（高 0.76 的点）；
> ② 台前亮池池心原来也用地面投影点，同样掉出画幅 ⇒ 改为以台面近边为基准按比例落点；
> ③ 光锥/灯位亮点是屏幕空间比例，不受影响。
> **遗留**：参考图台宽 0.284W 与"球员 0.33H 高"在真实透视下仍不可同时满足
> （球员 1.75m 与台宽 1.525m 的比值决定了两者的屏幕比例上限），v8b 取台宽 0.252W + 球员 0.47H 的折中。

## 二、观众席怎么铺的（v9：从远端 origin/main 恢复原版）

```
端看台（镜头对面那一侧）：z = ∓6.35 起，4 排，行距 0.50，行高 0.48，x 跨 ±5.2
侧看台（左右两条边）    ：x = ±(3.62 + row*0.55) 起，4 排，z 跨 ±5.5
步长 0.46（÷density）⇒ 满员约 376 人
座位：实体长椅（座面 0.2m + 高靠背），与观众行严格对齐
```

**关键坑：端看台只能放在"镜头对面"那一侧**（`crowdLayout(density, zSign)` 的 `zSign`）。
早先两头都放，横屏时另一侧正好在画面下缘之外看不出问题；**竖屏**（vh=844，纵向视野大得多）
会把它整排照进来 —— 实测竖屏截图里球台前方多出一排"挡在球员前面"的观众。
这条是 2026-10-22 的真 bug 修复，v9 回退观众席时**特意保留**。

> 布局缓存（`crowdListZ`）必须把相机侧纳入 key，否则本地双人换边（P2 视口）会看到背对镜头的那排。

## 三、观众怎么画的（坐姿火柴人）

```
画法   = drawPerson：圆头（arc，恰好 1 次/人）+ 躯干/大腿/小腿/手臂骨线（limb）
骨架   = seatedPose：面向球场中心，大腿前伸、小腿下落、手搭膝上；
         欢呼时举手+起身（bob），失望时摇头（headWig）
配色   = 队色 FAN_COL[240,110,92] / [110,160,246]（对局开始前按双方旗帜 setCrowdColors 覆盖）
阵营   = 屏幕左侧（世界 x<0）= 己方球迷，右侧 = 敌方；teamFixed 时分屏两端一致
分层   = 静态层（地板+看台+rest 观众，全分辨率缓存）/ 动画层（欢呼摇头，30Hz 烘焙）
```

**计数契约**（6 项观众测试依赖）：每位观众**恰好 1 次 arc**，且 arc 前 `fillStyle = 队色字符串`。
`drawPerson` 把这一次 arc 用在头上的圆。

**为什么 v9 把应援棒整体删掉**：2026-10-22~23 为忠于参考图的"光棒墙"做了屏幕空间粗圆头棒
（`drawPersonStick` + `CROWD_FX` + Kenney Light Masks 贴图），量化指标也确实更好看；
但用户明确要求回到原版观众席，于是以远端 `origin/main` 为基准整块回退，
代码（`drawPersonStick`/`CROWD_FX`/`CROWD_STYLE`/`neonise`/`CROWD_GLOW` 等）全部删除，
只保留亮度与顶灯。副作用是性能更好：静态层重建 2.0ms → **0.97ms**，空闲 123fps → **143fps**。

## 四、参数表（改之前先看这个）

全部在 `public/js/render.js`。**v9 起观众席是原版坐姿火柴人，几何参数直接写在
`crowdLayout()` / `benchLayout()` 里（不再有独立常量），可调项见下：**

| 参数 | 当前值（v9） | 作用 |
|---|---|---|
| `crowdLayout` 端看台 | z=±6.35 起 4 排、行距 0.50、x 跨 ±5.2 | 远端原版几何 |
| `crowdLayout` 侧看台 | x=±(3.62+row×0.55) 4 排、z 跨 ±5.5 | 远端原版几何 |
| `crowdLayout` 步长 | 0.46（÷density） | 满员约 376 人 |
| `crowdLayout` zSign | 按 `cam.eye.z` 定 | **只生成镜头对面那侧端看台**（竖屏 bug 修复，勿删） |
| `benchLayout` | 座面 0.2m + 高靠背，与行对齐 | 实体长椅 |
| `CROWD_R` / `CROWD_OUTLINE` | 0.028 / rgba(15,20,28,0.45) | 骨线粗 / 描边 |
| `FAN_COL` | 240,110,92 / 110,160,246 | 观众队色（原版；对局前按旗帜覆盖） |
| `CROWD_CAM_BUCKET` | 0.06 | 相机移动重建阈值 |
| `CROWD_ANIM_HZ` | 30 | 欢呼动画烘焙频率 |
| `LIGHT_AMB.volCenter/Edge` | 0.55 / 0.30 | 光锥内/外强度 |
| `LIGHT_AMB.volBottom` | 0.70 | 光锥落到的画面高度（t0>0.62 起淡出） |
| `LIGHT_AMB.darkTop/Mid/Bottom` | 0.58 / 0.22 / 0.22 | 纵向压暗 |
| `LIGHT_AMB.floorNear/Far` | 128,58,40 / 152,76,44 | 地板椭圆颜色 |
| `LIGHT_AMB.vigSide/Corner` | 0.16 / 0.45 | 四角暗角 |

> 差值大的档位用一段脚本按 (h,s,v) 分桶定位，比肉眼准得多——"暗场蓝灰雾"、
> "高饱和档缺口"、"品红档缺口"三个结论都是这么得出的。

## 五、验收（不用手点浏览器）

```powershell
# 真实对局截图（桌面 + 手机横屏）+ 帧率 + 亮区占比

# 机位反解（改了地标目标值后重跑）

```
