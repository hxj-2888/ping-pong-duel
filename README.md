# 乒乓对决 · Table Tennis Duel

按 **ITTF 国际赛事标准**球台尺寸做的双人乒乓球对抗，人物是**火柴人物理骨架**（两段式 IK + 弹簧阻尼惯性）。
前端零依赖、不需要 `npm install`，联机后端是手写 WebSocket 与 Cloudflare Durable Object 两套同源实现。

- 在线试玩（含公网联机）：<https://ping-pong-duel.pages.dev>
- 本地跑：`node server.js` → <http://localhost:8765>（Node.js 18+）
- 版本：**3.6.1**（安卓 `versionCode` 38）

---

## 一、能玩什么

| 模式 | 说明 |
|---|---|
| **单机人机** | 四档难度：简单 / 中等 / 困难，击败困难解锁**地狱**；开局菜单选定后**对局中锁定** |
| **无尽挑战** | 通关地狱后解锁，逐级挑战（关卡在对方球员的弹层里选，选择持久化） |
| **本地双人** | 同一键盘分屏，左右半屏各控一人，两套按键互不影响 |
| **AI 对打** | 先看双 AI 对决：可选**看台侧视角**或跟随甲/乙的**球员视角**；暂停面板可分别调甲/乙难度与 4 项 AI 参数 |
| **联机对战** | 4 位房间码。局域网内两台设备直连，公网直接访问上面的站点，无需端口转发 |
| **能力训练 / 战功系统** | 训练关卡、战斗奖励特效、生涯战绩与本机历史回放 |

战绩每局自动记录（总场次 / 胜 / 负 / 胜率 + 分页战绩：模式 · 难度 · 比分 · 时间 · 玩家名），后端保留最近 60 条；离线或无后端时静默不提示。

## 二、操作

| 动作 | 玩家 1（红方） | 玩家 2（蓝方） |
|---|---|---|
| 左右移动 | `A` / `D` | `←` / `→` |
| 前后移动 | `W` / `S` | `↑` / `↓` |
| 跑步 | `Shift`（本地双人用左 Shift） | `右 Shift` |
| 蹲下 | `Ctrl`（本地双人用左 Ctrl） | `右 Ctrl` |
| 推球 | `左键` / `F` | `,` |
| 扣球 | `右键` / `G` | `.` |

- **发球时**移动鼠标瞄准对方半台落点，轨迹线实时跟随，单击/右键发球；若瞄准处解不出合法发球，轨迹线消失且发不出球（要调整瞄准）。发球时限 **6 秒**，超时判对方得分并消耗本次发球机会。
- **对打时**左键立即推球（零延迟）、右键扣球；左键推球后 **280ms** 内按右键可把蓄力期推球升级为扣球。
- 人机与联机模式下 WASD 与方向键都能控制自己；**移动中也能击球**，球员可在己方半场自由前后左右走位（整身不上台）。
- **手机端（横屏化）**：竖屏持机显示「请旋转手机」遮罩，安卓包锁横屏。横屏下左下浮动摇杆移动（按下处生成、可斜向），右侧蹲下按钮；发球点两下屏幕（第一下瞄准、第二下出手），对打单击推球、**快速上滑扣球**。

## 三、击球判定：进箱即命中

接球不靠帧数玄学，而是一个**跟随球员的碰撞箱**：以球员为中心、向网前偏移 **0.42m** 的长方体，**1.2m 宽 × 0.8m 深**，站立时可接球高 **0.70~1.40m**。球进箱后按推球/扣球即命中，球拍自动伸向球完成动画。

- **蹲下**（`Ctrl`）把箱体下探到 **0.02m**——任何还在空中的低球都能接起；蹲得越久移动越慢（×0.40 → 最低 ×0.20，蹲满 2 秒到底）。
- 蹲↔站切换初始瞬发，但 **3 秒窗口内反复蹲站会累积转换延迟**（每次 +0.15s，上限 0.5s）。
- **扣杀来球有免起拍延迟命中窗**：挥拍 0~0.28s 内、球在箱内即命中，不需要提前起手。

### 四个能打出胜负的技巧

| 技巧 | 输入 | 效果 |
|---|---|---|
| 推球 | 左键 / `F` | 弧线抬高、带下旋（卸力吸收来球速度），干净过网 |
| 扣球 | 右键 / `G` | 约 22m/s+，贴网下压 + 强上旋；**击球点不够高（约 <1.0m）直接撞网失分**，不会降级成慢球 |
| **高吊球** | 蹲下 + 推球 | 高弧线喂到对方半场，逼对手起板扣杀（仅对普通来球生效，球太低会自动退回普通防守回球） |
| **反击扣杀** | 预判起拍（球到前提前按推球）+ 推球 | 站立即可接回对手扣杀，且**该回球视为扣杀、对手应对概率减半** |

低平快球用**蹲下 + 推球**接回回报更高：球速更快 + 落点更刁，同样视为扣杀、应对概率减半。

## 四、AI 的行为差异

| 难度 | 表现 | 接球率 |
|---|---|---|
| 简单 | 反应慢、站位偏、只推不扣 | 约 55%（明显漏接） |
| 中等 | 反应适中，高球常扣杀，会放高吊、打刁钻角度、变招 | 约 95% |
| 困难 | 反应快、追位准，高球必扣杀 | 约 97.5%（刻意漏球 <3%） |
| 地狱 | 全面拉满，**0% 刻意漏球**，扣杀激进（约 2~7 扣/局） | 差距全在时机与技巧 |

- **刻意低球**：困难 1/5、地狱 1/2 的概率打出贴网低飞的低平快球，站立箱底容错极小，蹲下接最稳；简单/中等不打。
- **变招**：对打两回合不进球后可能改打低平快/高吊并横向移动 0.4~0.7m，概率随难度上升、久未变招会累积。
- **应对扣杀**：先判「落点是否在站位 ±0.35m 内且高度时序成立」，再按档位概率接住（困难 55%、地狱 95%）；打边角、骗位就会漏。
- **AI 也会自己撞网**：判定无法扣杀时，困难 80% / 地狱 90% 改打安全球，剩下 10~20% 冒险出手 = 球撞网失分（和玩家右键同一套规则）。
- 击败地狱后，人机暂停面板会变成 **4 项 AI 参数滑杆**（反应 / 接球率 / 攻击性 / 敏捷），可以自调对手强度。

## 五、物理与规则

**ITTF 标准尺寸**（真源：`public/js/engine/rules.js`）

| 项 | 值 |
|---|---|
| 球台 | 2.74m × 1.525m，台高 0.76m，台厚 0.035m（白线 2cm） |
| 球网 | 高 0.1525m，宽 1.525m（两端与台面边缘相切） |
| 乒乓球 | 直径 40mm，质量 2.7g |
| 球拍 | 拍面 15cm × 15cm，手柄 8.5cm |
| 球员 | 1.75m 比例骨架，横向移动 3.2m/s，跑步 ×1.30 |
| 重力 | 9.81 m/s² |

**飞行与规则**

- 真实重力 + 空气阻力 + **马格努斯旋转效应**，台面反弹带摩擦，旋转会在落台时改变前后速度。
- 发球必须**先落本方半台、再越网落对方半台**；擦网重发。
- 拦击（球未落台直接打）判失分；同一半台连弹两次判失分。
- **11 分制**，10 平后净胜 2 分；每 2 分轮换发球，10 平后每分轮换。
- 站位保护：发球方持球期间身体被钳在离网 ≥1.25m 处（否则任意站位都能解出合法发球，落点环会翻到网对面）。

## 六、画面与人物

- **火柴人骨架**：髋→脊柱→肩→颈→头、肩→肘→腕→拍、髋→膝→踝→足，全部**两段式 IK**；关节带弹簧-阻尼惯性，急停变向有动量感，头部实时注视球，击球后手臂顺动量回摆。
- **球衣与拍面主色跟随队色**（8 种可选，撞色自动互换，队名限 6 字）；己方视角只显示上半身。
- **赛场氛围**：场地两端与两旁是坐姿火柴人观众（与球员同画风）坐在钢蓝色看台长条座椅上，左红右蓝各自在屏幕左侧看到本方球迷；**哪方得分哪方球迷举手欢呼、对方摇头**。
- **声音**：得分播放真实掌声录音（`audio/applause.wav`，未加载时用 WebAudio 合成兜底），背景音乐 `audio/music.mp4` 取音频轨循环，与音效开关完全独立。
- **物理反馈**：击球火花、高速球运动拉伸、击球/落台/触网/得分触发镜头震屏 + 推近（分屏两半各自围绕视口中心，不撕画面；低画质自动减半，设置里可关）。
- 低机位转播相机，红方视角水平镜像使按键方向与屏幕一致；球带台面/地面阴影，触台有扩散红圈。

## 七、设置（主页与比赛页通用，右上角 ⚙）

判定范围虚线（默认关闭，随时可开；开启后显示接球箱线框、球进箱变绿并提示）、背景音乐、游戏音效、**音乐/音效音量独立滑杆**、画质（高 / 中 / 低，低档跳观众席并降 DPR）、帧率上限（30 / 60 / 无上限，只限渲染频率，物理步长不变）、比赛视角（第三人称 / 第一人称，人机、分屏、联机、AI 观战、回放全部生效）、按键指示。所有开关即改即生效并记忆；右上角实时显示真实渲染帧率，低于 45 变黄提示。

## 八、联机与后端

两套同源实现，房间语义镜像：

| 场景 | 实现 |
|---|---|
| 本地 / 局域网 | `server.js`：**零依赖手写 RFC6455 WebSocket** + 静态服务，监听 `0.0.0.0:8765`（`PORT` 可改），**服务器权威模拟 60Hz 固定步长**，双方输入统一结算后广播快照 |
| 公网 | Cloudflare Pages 高级模式（`public/_worker.js`）把 `/ws` 反代到独立的 **Durable Object** Worker `game-room`（`src/room.js` + `src/room-core.js`），房间状态用 DO storage 持久化，实例驱逐后可恢复 |

- **局域网对战**：房主起服务并「创建联机房间」，等待面板会直接列出本机各网卡的 `http://<IP>:8765` 地址；对方浏览器打开该地址（游戏从房主机器加载，无需另装），输入 4 位房间码加入。Windows 防火墙默认挡入站，需放行 TCP 8765。
- 房间有**断线宽限**：连接静默 15 秒后席位进入宽限，重连按 `side` 接管旧连接；宽限到期仍未重挂才释放席位并通知对手，避免一次网络抖动直接终结对局。
- `GET /api/info` 返回 `{ version, port, ips }`；战绩走 `GET/POST/DELETE /api/records`（DELETE 需维护 token）。
- 客户端 `public/js/network.js` 负责握手重试、输入缓存与身份过滤。

## 九、部署

```bash
npx wrangler deploy --config wrangler.room.toml      # 先部 DO Worker（game-room）
npx wrangler pages deploy public --branch main       # 再部 Pages 静态站
```

顺序不能颠倒：Pages 的 `/ws` 依赖 `game-room` 的 DO 绑定。PWA 离线缓存名随版本递增（当前 `ppd-v361`），APK 下载不拦截不缓存。

## 十、目录结构

```
ping-pong-duel/
├── server.js                # 本地/局域网联机服务器 + 静态服务（零依赖手写 WebSocket，60Hz 权威模拟）
├── desktop-launcher.js      # 桌面启动器（拉起/重启本地服务器，读 /api/info 版本）
├── wrangler.toml            # Pages 配置（高级模式 _worker.js + DO 绑定）
├── wrangler.room.toml       # game-room Durable Object Worker 配置
├── public/                  # 前端 = Pages 发布目录
│   ├── index.html           # 主页与比赛界面
│   ├── download.html        # 安卓 APK 下载页
│   ├── _worker.js           # Pages 高级模式：静态资源 + /ws 反代到 DO
│   ├── manifest.webmanifest / sw.js   # PWA 清单与离线兜底
│   ├── _headers             # 缓存与安全响应头
│   ├── css/ audio/ assets/  # 样式、真实掌声/BGM、场景贴图
│   └── js/
│       ├── engine.js + engine/   # 共享物理引擎（UMD，math/physics/rules/shots/strokes/state 六个子模块）
│       ├── render.js             # 轻量 3D 投影渲染：球台/球网/观众席/特效/发球轨迹
│       ├── characters.js         # 火柴人骨架（2-Bone IK + 弹簧阻尼）
│       ├── ai.js                 # 人机对手（四档难度 + 参数滑杆，纯逻辑可脱离浏览器运行）
│       ├── audio.js              # WebAudio 音效合成 + 真实音频加载
│       ├── boot-loader.js        # 进场加载门：图像与音频就绪后才开主菜单
│       ├── network.js            # 联机客户端（握手重试 / 输入缓存 / 身份过滤）
│       └── app/                  # 业务层 15 模块（IIFE + window.PPD 命名空间）
├── src/                     # 云端 Worker：index.js 入口、room.js（DO）、room-core.js（房间核心，与 server.js 语义镜像）、engine/（引擎 ESM 镜像）
└── docs/                    # 图标署名与赛场参考规格
```

引擎在 `public/js/engine*`（浏览器 UMD）与 `src/engine*`（Worker ESM）两份存在，**逐字节镜像**——改一份必须同步另一份，否则本地和公网的物理会慢慢分叉。
